# fm1-assets

[![crates.io][crate-badge]][crate]
[![docs.rs][docs-badge]][docs]
[![Build status][ci-badge]][ci]

Embed read-only assets in FM-1 execute-in-place flash and stream lossless mono
PCM16 without a heap or a decoded block buffer. The target library has no
dependencies on the BSP or WaveGraph.

## Flash layout

Depend on `fm1-assets` and use `-C link-arg=-Tfm1-assets.ld` in place of
`-Tfm1.ld`, or write `INCLUDE fm1-assets.ld` in an application linker script.
This opts into a combined code and factory-data budget ending at physical
`0xE0000` (exclusive). The boot area is `0x0000..0x4000`. Reserve a smaller
application area with a linker assertion on the end of `.fm1_assets` if
your firmware keeps persistent state inside that range.

Use `flash_asset!(u8, include_bytes!("..."))` for bytes, or supply a slice of
another `Copy` element type. The macro places the array itself at its natural
alignment. A reference stored in an array still points to its original backing
storage. An unreferenced license notice can use an immutable `#[used]` static
in input section `.fm1_assets.keep`.

The first asset starts on the next 4 KiB boundary after the final flash load
byte, including the initial values of RAM data. The default BSP script keeps
the stock app.bin limit for ordinary builds. Older BSP releases also keep
that limit for app.bin when used with this script. Assets can still extend to
the combined ceiling. Increasing app.bin beyond the stock limit requires the
BSP script with support for `__fm1_assets_xip_end`.

Package the linked ELF using the Python tool distributed with this crate
and the same pi32v2-isa checkout used for the firmware toolchain:

```sh
PYTHONPATH="$PI32V2_ISA/tools/hwtest" python3 path/to/fm1-assets/tools/package.py path/to/firmware
```

It produces the raw emulator `.bin` and M-Flasher `.fwsc` next to the ELF.
The package carries checksummed app.bin and assets.bin records and ends at
the last occupied sector. Supply at least one nonempty asset. Installing can replace another firmware's data
up to that boundary. Moving the boundary can require rewriting asset sectors.

## Packed mono PCM16

With `features = ["encode"]` on the **host build dependency**, call
`pcm::encode(&samples)`, then write the result into Cargo's `OUT_DIR`.
The encoder is available on hosted targets and uses `alloc`. Use default
features on the firmware dependency.
Validate the generated bytes once, preferably in a constant. Calling
`samples()` for a new note starts a fresh cursor in constant time.

```rust
use fm1_assets::{flash_asset, pcm::PackedPcm16};

const CLIP: PackedPcm16<'static> = PackedPcm16::parse(
    flash_asset!(u8, b"PCM1\x04\0\0\0\x02\x4b")
).expect("built-in clip");
assert!(CLIP.samples().eq([-1, -2, 0, 1]));
```

The PCM1 format starts with the four bytes `PCM1` and a little-endian u32
frame count. In each group of up to 32 frames, one byte gives the signed width
(1 through 16). Samples are two's-complement integers packed least-significant
bit first, followed by zero padding to a byte boundary. The decoder ignores
padding bits. Rate and channel routing belong to the application. Full-width
noise can take more space than raw PCM. Other encodings, including FLAC,
can be embedded with the same asset macro and linker script.

## Optional FLAC and WaveGraph samples

Enable `flac` with Rust 1.89 or newer. On pi32v2 this adds
`nanoaudio-flac` and `nanoaudio-core`. The default features of fm1-assets
enable neither. Encode files on the host with a known maximum FLAC block
size. A complete compressed file can stay in XIP. Keep one decoder per
independently playing stream and pass the unread input on each call.

Use `flac::Mono16::<128>::new()` for mono PCM16 encoded in blocks of up to
128 frames. Its target size is 952 bytes with nanoaudio-flac 0.1.2.
Call `decoder.decode(input, output_i16)` for the native sample type.
The optional adapter accepts a conversion function for other outputs:

```rust
# #[cfg(feature = "flac")]
# fn render(input: &[u8], bus: &mut [wavegraph_sample::I24],
#           decoder: &mut fm1_assets::flac::Mono16<128>) -> fm1_assets::flac::Result<()> {
use fm1_assets::flac::decode_as;
use wavegraph_sample::{I24, Sample};
let mut scratch = [0_i16; 32];
let step = decode_as(decoder, input, &mut scratch, bus, I24::from_sample)?;
// Advance input by step.consumed and output by step.produced.
# Ok(()) }
```

PCM16 to WaveGraph I24 is exactly a shift by eight. The adapter borrows
both slices and adds no dependency on WaveGraph. To retain 24-bit source
precision, select `FlacDecoder::<i32, 128, 1>` and use an i32 scratch slice.
For a complete in-memory stream call `finish()` on the decoder to signal that
no more compressed bytes will arrive. Use the stream's declared sample count
when checking playback or an asset import for truncation.
